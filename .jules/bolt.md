## 2026-06-15 - [Word-Count Truncation & Regex Backtracking Optimizations]
**Learning:** Calling `.split()` twice on huge files splits the entire document into an unbounded word list twice, which is extremely expensive for CPU and memory. Limiting split with `split(None, maxsplit)` completely avoids full-string splitting, speeding up the process by over 14x. Additionally, regular expressions like `re.sub(r'\{.*?\}', ...)` are vulnerable to catastrophic backtracking and heavy C-level overhead on unbalanced files; replacing this with a single-pass linear scan using `.find()` ensures $O(N)$ safe execution and perfect equivalence.
**Action:** Always use `maxsplit` when truncating words from large files, and prefer native string `.find()` linear scans over non-greedy regular expressions for processing massive corpora.
