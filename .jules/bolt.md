## 2026-07-21 - ChromeDB RAG Indexer Batching and Word Split Optimization
**Learning:** Full string splitting via `contenido.split()` on large text files (especially research corpora over 10MB) causes severe CPU and memory bloat. Replacing it with `contenido.split(None, 40001)` limits the split work to the required limit and avoids multiple full string splits. Furthermore, inserting documents one-by-one into ChromaDB creates significant API/IPC overhead, which is solved by batching document uploads in batches of 20 with robust buffer cleanups in `finally` blocks to prevent batch poisoning.
**Action:** Always prefer `maxsplit` arguments in python string splitting operations when only the prefix/limit of the text is required. Implement buffered batching with try-except-finally blocks for any vector store indexing loops.
