## 2026-06-25 - Redundant Full-String Splitting and Encoding Overhead in Python
**Learning:** Checking the word count of a large string by performing a full `.split()` and then taking a slice of the full split string performs redundant passes over the text and allocates substantial list memory. Utilizing the `maxsplit` parameter with `split(None, N)` allows Python to abort splitting early once the threshold is crossed, resulting in up to 76x-200x speedups. Additionally, encoding massive string buffers to UTF-8 just to track exact byte lengths incurs 1200x+ performance overhead compared to character length checks or querying file metadata directly.
**Action:** Always check if a full string split can be restricted with a `maxsplit` boundary when only a prefix length or presence of a threshold is needed. Avoid `.encode('utf-8')` calls in loops; use file-system size queries (`os.path.getsize`) or character-length approximations instead.
