## 2026-03-29 - ChromaDB RAG Indexer Batching and Word Truncation
**Learning:** Performing single-document `collection.add(...)` in ChromaDB incurs severe overhead per item (individual DB transactions and sentence-transformer inference with batch size 1). Additionally, checking length and slicing long strings with `len(contenido.split())` and `contenido.split()[:40000]` performs full string splits on large texts twice, allocating millions of string objects unnecessarily. Using `contenido.split(None, 40000)` reduces word-truncation time by ~18x-20x, and batching ChromaDB inserts in groups of 20 dramatically speeds up vector indexing.
**Action:** When working with Python text processing and vector databases, always use `str.split(sep, maxsplit)` to avoid splitting beyond required limits, and batch database vector insertions into groups of 20-50 documents.
